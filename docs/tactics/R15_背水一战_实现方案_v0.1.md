# R15 背水一战 avoid / UX：AI「何时该用、不该用」实现方案 v0.1

- 日期：2026-10-26
- 来源：工单 #25 用户标记「第 24 回合 升象+背水一战」为笨棋（原话：“背水也没用明白，直接象动两下就行了，将没必要动”）；K22-1 是它的 UX/avoid 回归题。
- 目标：不是“学会用背水翻盘”（那是会用侧），而是**别把每局一次的背水浪费在无用换位上**；被迫解将时也要在能解的组合里挑冻结代价最小的，而不是随手把将挪走。
- 分工建议：Balance 做代码 + 对打/回归，战术部门出题与验收。
- **配套验收清单**：`R15_背水一战_验收点_v0.1.md`（K22 候选清单/排除与偏好、冻结罚分排序、非被迫 fixture、单测断言）；非被迫测试局面 `tactics/positions/r15-nonforced.json`。

## 一、机制事实（引擎侧，先对齐）

1. **背水一战**（`CFG.beishui.on`，楚方主帅兵法）：每局一次、一次两步（两步行棋），可动用条件 = 楚方车马炮 ≤3 枚且少于对方（`artOpen`）；两步走完**不能让汉方被将军**；**用过的子下回合被冻结**（`S.fx`/`bz`，`strictEscape` 下只有“被将军时吃子解将”才能动）。
2. 背水是“翻盘 / 救急”用：AI 估值里未用的背水记 +3 分（`BSV`），真用掉要拿回价值；使用门槛 `BSMIN=1`（用背水要比最好的普通走法多赚 ≥1 分才用）。破釜沉舟时代门槛 4.5。
3. 当前实现（`game-repo/source/src/bfai.js`）：
   - 根候选 `pofuPairs`（`bingfa.js`）：普通局面只枚举“两步里至少一步打到敌子”的组合；**楚被将军时** `bsDef=true`，才把“两步都不打子”的解将组合也列出来。
   - 过滤/排序：静态 gain ≥2（BS）/4.5（破釜）或已分胜负；被将军时不设门槛；只留前 8（`bfai.js` L625-637）。
   - 抉择：`need = bestV + BSMIN`，逐个用 `-ab(...)` 深搜，值 ≥need 才用背水（L757-771）。
   - **特例（K22 场景）**：普通着法一步都没有（被将死的样子）但背水能解 → 直接 `pofu[0]`（静态 gain 最高），**不深搜、不考虑冻结代价**（L659-661）。
4. K22 局面实测：`specs/issue25-24楚.json`（第 24 回合）楚被将军、普通走法 `expand=0`；当前 main 引擎 `pofuPairs(S)` 只有一个组合（将 5,7→5,8→5,9）；而实战 r13b 走了“升象(6,9)+背水（将 5,7→4,7、象 6,9→4,7）”，用户标笨。

## 二、问题定义（要修的三种表现）

- **P1 被迫解将时随手换将**：kids=0 时直接取静态最优，没有比较“解将后是否还安全 / 冻结了谁”。将一被冻结，下一回合九宫更危险。
- **P2 非被迫时防守型背水没有候选**：两步都不打子的“脱险/归位”组合只在被将军时才枚举 → “直接象动两下”这种不靠吃子的用法永远不在考虑范围。
- **P3 冻结代价没有显式估值**：冻结将/车的代价只靠搜索里“走不了”间接体现，浅层（尤其 3 秒 depth4）来不及算出来。

## 三、实现方案（单个开关 `BFAI_BSX`，分三步、可独立开）

### 步骤 1（核心，修 K22/P1）：被迫解将时“择优 + 冻结罚分”

- 触发：`kids.length === 0` 且 `pofu.length > 0`（`bfai.js` L659 分支）。
- 改为：对 pofu 列表里每个组合（含“先升级再背水”），做**深度 1–2 层搜索**（`-ab(k.S, 2, ...)`，节点上限约 1/8 步预算；此分支很少出现，成本可控），排序键：
  `值 − 冻结罚分`，冻结罚分按被冻结子计：**将 −1.5、车 −0.8、炮/马 −0.3、士/象/兵 −0.1**。
- 选择：取“解将后不被将死、且下一步不被贴脸一步杀”的最高分组合；若全部都会被将死，再退回现有 `pofu[0]`。
- 预期：K22 不再首选举“将+象”换位（冻结将 −1.5）；优先“将两步”或“士/象解将”里冻结代价小的。

### 步骤 2（可选，修 P2）：非被迫的“防守型背水”候选

- 放宽 `pofuPairs` 的“至少打一子”过滤，但只在限定局面生成，避免分支爆炸：
  - 条件（任一）：① 两枚被威胁子两回合内会被吃（用 `killable` 类判定），两步都能脱身；② 两枚象/士归位（九宫被压 + 背水可两步入位）；③ `score` 显示两枚子同时受攻。
  - 数量上限 8、gain 门槛保持 ≥2；仍走普通根候选的搜索流程（需要 `pick` 时用 `need=bestV+BSMIN`），不会乱用。
- 建议先只在兵仙/霸王档、且开关默认关；有对打数据再考虑默认开。

### 步骤 3（可选，修 P3）：冻结代价进 `score`

- 只对 `S.fx` 里未到期的冻结子加显式扣分：将 −1.0、车 −0.5（其它不动）；作用在 `score()` 的“子力/位置”分项里，保证浅层也能感到代价。
- 注意：普通局面分值不能变（只在有冻结时生效）；改完必须跑 K12/K18/实27/K20/K21/K23 回归。

## 四、明确不做什么

- **不硬编码“象走两下”这种具体着法**——背水两步允许同一子连走，具体哪两下要看局面；引擎只做“值 + 冻结代价”的一般化排序。
- 不改普通走法的估值去迁就背水；不改破釜时代的 4.5 门槛与非被迫“多赚一大子才用”的翻盘逻辑（那是会用侧的正向逻辑）。
- 不为了 K22 过题而放宽题面：K22 是 avoid（只排除用户标的这串换位），r15 走任何别的合法解将组合都算过。

## 五、验收（战术部门出题、Balance 跑）

1. **K22-1 3 次**（avoid）：r15 应过（不再走“升象+将/象换位”那串）；不要求固定正解。
2. **考卷回归**：K20-1/K21-1/K23-1 不退化；全卷 ≥ 当前 r13b 基线。
3. **对打**：r15 对 r13b 600 局（time:3000）先跑校准（r13b 对 r13b 应落 46%～54%），再看背水开关不亏分；背水每局一次、触发少，预期差异小（z 不显著就按“不亏”结案）。
4. **时间成本**：步骤 1 只在被将军且无普通着法时触发（极少数局面），预计每步平均增加 <1%；步骤 2/3 默认关，需要数据支持再开。
5. **题面补充（可选）**：从真对局里扫“背水可用但不必用”的非被迫样本（例如 30 回合后仍握着背水、有子被吃却不用），做一道“别浪费背水”的会用/会防题；需 time:3000 下稳定（同尺 + 两档一致性）才收。
