# Native difficulty experiment

Preparation branch: `bench/formal120-55919`. No formal run is enabled until the latest candidate is installed and the launch file is committed.

Candidate handoff: copy only the authorized AI JavaScript into `ai/candidate.js`, byte-for-byte, and set its full SHA-256 in `config/formal120.json` (`expectedCandidateSha256`, required prefix `55919a98`). Both competitors load this one file. Do not upload the evidence ZIP or private documentation. Keep `ai/baseline.js` and `ai/opening.js` as historical files; neither is used in this experiment. Update the candidate entry in `config/manifest.json` and its provenance to identify the actual imported source. If the supplied identifier is not a SHA-256 prefix, resolve that discrepancy before changing the identity gate.

Run `npm run verify`, `npm test`, and `node tools/formal120.js preflight`. Only after verifying the full candidate hash, create `config/launch120.json` containing `{"candidateSha256":"FULL_VERIFIED_SHA256","games":120}` on this branch. That path alone triggers `.github/workflows/formal120.yml`; preparation commits do not trigger it. Do not edit the launch file again or rerun the workflow: attempt 2+ is disabled to prevent repeating seeds. No permission or runner billing changes are needed.

The first job validates the sources, then runs two short one-round smoke games using native time budgets and swapped levels. These are diagnostic truncations, excluded from the formal 120. Only successful smoke validation unlocks 60 pair jobs. Formal seeds are 610150000–610150059; smoke uses 610149999. Both games in a pair start from the standard position with the same RNG seed, with A=hard and B=xhard swapping colors. No opening AI or node cap is injected. Native hard=3000ms/minNodes=20000 and xhard=9000ms/minNodes=60000 must match the imported candidate. Its dynamic budget behavior is preserved; these budgets are not strict elapsed-time limits.

Each standard `ubuntu-24.04` runner uses one simulator worker. At most four pair runners execute concurrently. Each pair has an 80-minute process-group deadline inside a 90-minute job; 150 rounds is the game cap. There is no paid/larger runner, deployment, automatic retry, or expansion to 300 games.

Each pair retains metadata (source/rules/runner/config hashes, commit, runtime, seed), exact command, simulator log, per-game streaming JSONL, raw results, validation and replay results, and status/summary. Journal records include thinking start, effective level configuration, decision start/end, actual nodes/depth, actions, terminal state and reason. A killed game retains its last thinking/decision event and an explicit wall-timeout/incomplete status. Capped, stuck, probe and interrupted games are unresolved, never draws. All workflow artifacts are retained for seven days. The final job verifies completeness and produces `formal120-summary.json`; missing pairs are reported without rerunning them.
